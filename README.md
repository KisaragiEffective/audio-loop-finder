# audio-loop-finder

オーディオファイル中の繰り返し区間（ループポイント）を自動的に検出するツールです。  
FFT ベースのスペクトル特徴量と **コサイン類似度** を組み合わせて、音響的に似ている箇所のペアを高速に探します。

## 使い方

```
audio-loop-finder [OPTIONS] <FILE>

引数:
  <FILE>  解析対象の音声ファイル (ogg / wav / mp3)

オプション:
  --minimum-length <SECONDS>      マッチしたペア間の最小時間差 (秒)
  --minimum-similarity <0.0–1.0>  最小類似度閾値
  --limit <N>                     表示件数 (デフォルト: 5)
  --timestamp-range <START-END>   指定範囲内のタイムスタンプのみ表示 (複数指定可)
```

## 類似度計算の仕組み

### 1. フレーム分割とハン窓

音声データを **ホップサイズ** ごとにスライドしながら **4096 サンプル** ずつ切り出し、各フレームに **ハン窓** を掛けます。

```
w[n] = 0.5 * (1 - cos(2π·n / (N-1)))    (N = 4096)
```

ハン窓を掛けることで、フレーム端のスペクトル漏れ（spectral leakage）を抑制します。

### 2. FFT とマグニチュードスペクトル

ハン窓を掛けたフレームに対して **FFT** を実行し、各周波数ビンの **振幅**（magnitude）を求めます。  
位相情報は使用せず、音色・音量の大まかな分布のみを捉えます。

### 3. 対数周波数バンドへの集約

FFT の 2049 本の周波数ビン（4096/2 + 1）を、**対数スケール** で均等に区切った **64 バンド** に集約します。  
各バンド内のマグニチュードの平均をバンドのエネルギーとします。

対数スケールを用いる理由は、人間の聴覚が周波数を対数的に知覚するためです（低域の変化に敏感、高域は相対的に鈍感）。  
これにより、メルスケールに近い知覚的に妥当な周波数表現が得られます。

### 4. L2 正規化

64 次元のバンドエネルギーベクトルを **L2 ノルム** で正規化し、単位ベクトルにします。

```
v_normalized = v / ||v||₂
```

これにより、音量の違いを吸収して「音色・周波数分布の形」だけで比較できるようになります。

### 5. コサイン類似度（内積）

L2 正規化された 2 つのフレームベクトル **a**、**b** の類似度は **内積**（ドット積）で計算されます。

```
similarity = a · b = Σ aᵢ × bᵢ
```

単位ベクトル同士の内積はコサイン類似度に等しいため、値域は **−1〜1** です（バンドエネルギーは非負なので実際は **0〜1**）。  
値が 1 に近いほど音色・周波数分布が似ていることを意味します。

## 他の計算方法との比較

### コサイン類似度（本ツールで採用）

| 観点 | 内容 |
|------|------|
| **メリット** | ・音量差に不変（L2 正規化済み）<br>・計算が高速（内積のみ）<br>・対数周波数により人間の知覚に近い比較が可能 |
| **デメリット** | ・各フレームを独立に比較するため、時間的なつながりを考慮しない<br>・位相情報を無視する<br>・音色の細かなニュアンスは MFCC より劣る場合がある |

---

### ユークリッド距離（L2 距離）

$$d = \sqrt{\sum (a_i - b_i)^2}$$

| メリット | デメリット |
|---------|-----------|
| 直感的でシンプル | スケール（音量）の変化に敏感。正規化しないと音量違いが大きく影響する |
| 絶対的な距離を表す | コサイン類似度に比べ、方向の違いよりもスケールの違いを強調してしまう |

---

### MFCC（メル周波数ケプストラム係数）＋ DTW

人間の音声・音楽認識モデルとして広く使われる特徴量。ケプストラム変換で音色の包絡を取り出します。  
DTW（Dynamic Time Warping）と組み合わせると、速度変動があっても柔軟にマッチングできます。

| メリット | デメリット |
|---------|-----------|
| 音声認識で実績のある知覚的特徴量 | 計算コストが高い（特に DTW は O(N²)） |
| 時間的な伸縮に対応（DTW 使用時） | ループ探索のようなフレーム単位比較には過剰な場合がある |
| デルタ（速度）特徴量も追加可能 | 実装が複雑 |

---

### クロマ特徴量（Chroma）

半音階ごとの音高クラス（12 次元）を表す特徴量です。

| メリット | デメリット |
|---------|-----------|
| 調性・和音の類似性を捉えるのに優れる | 音色や音量の情報を持たない |
| 転調した曲でも比較しやすい | リズムや打楽器成分に弱い |

---

### スペクトルフラックス（Spectral Flux）

隣接フレーム間のスペクトル変化量を測る指標です。

| メリット | デメリット |
|---------|-----------|
| 音のオンセット（打鍵・アタック）検出に強い | フレーム間の変化量なので、絶対的な音色比較には不向き |
| ビートやリズムの一致を評価するのに向く | ループポイント探索よりもビート検出向き |

---

### マンハッタン距離（L1 距離）

$$d = \sum |a_i - b_i|$$

| メリット | デメリット |
|---------|-----------|
| 外れ値（突出した周波数成分）の影響を受けにくい | コサイン類似度ほど方向（音色の形）を正確に比較できない |
| 計算が高速 | スケール不変性がないため正規化が必要 |

---

## まとめ

本ツールの「**対数周波数バンド ＋ L2 正規化 ＋ コサイン類似度**」という組み合わせは、  
ループ探索という用途において以下の理由から合理的な選択です。

- 対数バンドにより人間の知覚に近い比較が可能
- L2 正規化により音量差を無視して音色の類似性を評価
- 内積計算のみで非常に高速（全フレームペアの O(N²) 比較が現実的）
- ループポイントは「同じ音が鳴っている箇所」であるため、フレーム単位の比較で十分

DTW や MFCC は音声認識・音楽検索に強力ですが、本ツールのユースケースでは計算コストに見合わない場合があります。
